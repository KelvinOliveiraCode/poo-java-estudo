01 Base: classe e objeto CIANO

Classe é o molde. Objeto é o que nasce dele, com valores próprios.

O molde gera objetos

classe → objetos
class Televisor volume · ligada · marca

Pronto. O molde ainda não gerou nada.

Criar objeto em 3 passos

declarar → new → construtor
Televisor tv
objeto no heap volume 0 · ligada false · marca null
—

Passo 0 de 3.

Código mínimo

public class Televisor {
  int volume;        // 0
  boolean ligada;    // false
  String marca;      // null

  void aumentarVolume() {
    volume++;
  }
}

Televisor tv = new Televisor();
tv.aumentarVolume();  // mensagem
  • Classe = molde; define atributos (estado) e métodos (comportamento).
  • new = instancia: reserva memória e chama o construtor.
  • tv = referência; guarda o endereço do objeto, não o objeto.

Como reconhecer na prova

  • class Nome { ... } com atributos e métodos → definição de classe.
  • Tipo var = new Tipo(); → criação de objeto (3 passos juntos).
  • Valores default: 0, false, null — sem inicialização explícita.
  • Um objeto chamando método de outro → mensagem.

Erro comum

Achar que tv é o objeto. tv é a referência. Se ela é null, o objeto não existe e o acesso gera NullPointerException. Os 4 pilares: abstração, encapsulamento, herança e polimorfismo.

02 Escopo e static MAGENTA

Sem static cada objeto tem o seu. Com static todos dividem o mesmo valor.

Um valor para todos

Classe.atributo
ÚNICO NA MEMÓRIA · static
Celular.empresa —

Pronto. Crie os celulares.

Código: instância x classe

public class Celular {
  String numero;          // instância
  static String empresa;  // classe

  static {                // roda 1 vez
    empresa = "Tech";
  }

  static void trocar(String e) {
    empresa = e;          // sem this
  }
}

Celular a = new Celular();
a.numero = "1111";
Celular.empresa = "Nova";
  • static = um só valor para a classe inteira, mesmo com 1000 objetos.
  • bloco static { } = inicializa membros estáticos uma única vez, quando a classe é carregada.
  • Método static não acessa membros de instância diretamente: não existe this ali.

Como reconhecer na prova

  • static no atributo/método → pertence à classe, acesso Classe.membro.
  • static { ... } → bloco de inicialização estática (executa uma vez).
  • Contador de instâncias, constantes e fábricas costumam ser static.

Pegadinha

Dentro de um método static, tentar usar numero ou this gera erro de compilação: não há objeto. Uma vez criado, o static é compartilhado — mudar em um ponto muda para todos.

03 Encapsulamento VERDE-LIMÃO

Tranque o atributo com private e só deixe entrar pelo get/set validado.

O cofre da idade

private + validação
private int idade 30
porta do set 0 a 120
—

Digite um valor e tente os dois acessos.

Matriz dos modificadores

toque em um modificador
acesso mesma
classe		 mesmo
pacote		 sub-
classe		 outro
lugar
private✔sim✖não✖não✖não
package✔sim✔sim✖não✖não
protected✔sim✔sim✔sim✖não
public✔sim✔sim✔sim✔sim

private: só a própria classe enxerga.

Da ordem do mais restrito ao mais aberto.

Código: o set valida

public class Pessoa {
  private int idade;   // trancado

  public int getIdade() {
    return idade;
  }

  public void setIdade(int idade) {
    if (idade >= 0 && idade <= 120) {
      this.idade = idade;
    }
  }
}

p.setIdade(30);   // passa
p.setIdade(-5);   // ignorado
  • private esconde o atributo; ninguém mexe direto.
  • set aplica a regra de negócio: só aceita 0 a 120.
  • get devolve o valor sem expor a implementação.

Como reconhecer na prova

  • private + get/set → encapsulamento.
  • Validação dentro do set → regra de negócio protegida.
  • Ordem: private → package (sem modificador) → protected → public.
  • protected = mesmo pacote + subclasses (mesmo em outro pacote).

Erro comum

Criar get/set que não validam nada: o atributo fica “escondido”, mas qualquer valor entra. Encapsular é proteger a regra, não só trocar public por private.

04 this ROSA

this aponta para o objeto que está executando o método agora.

Atributo x parâmetro

this.canal = canal
parâmetro canal = 7
atributo do objeto canal = 1
this.canal = canal;

O nome é igual; o que muda é o dono.

Código: os dois usos

public class Televisor {
  private int canal;

  public Televisor(int canal) {
    this.canal = canal;  // objeto = parâmetro
  }

  public Televisor() {
    this(1);             // 1ª linha
  }
}
  • this.canal = atributo do objeto corrente.
  • canal (sem this) = parâmetro do método.
  • this(1) chama outro construtor da mesma classe — precisa ser a 1ª linha.

Como reconhecer na prova

  • this.x = x; → diferenciar atributo de parâmetro.
  • this(...) na primeira linha do construtor → reutiliza outro construtor.
  • return this; → retorna o próprio objeto (encadeamento).

Pegadinha

Sem this, canal = canal atribui o parâmetro a ele mesmo; o atributo continua 0. E this não existe em método static. Já this(...) fora da 1ª linha não compila.

05 Construtores ROSA

Construtor tem o nome da classe, não tem retorno e deixa o objeto pronto.

Qual construtor foi chamado?

sobrecarga
objeto volume · canal
Nenhum objeto ainda.

Três construtores, três resultados.

Código: sobrecarga de construtores

public class Televisor {
  int volume, canal;

  Televisor() {
    volume = 0; canal = 1;
  }

  Televisor(int volume) {
    this(volume, 1);      // chama o 3º
  }

  Televisor(int volume, int canal) {
    this.volume = volume;
    this.canal = canal;
  }
}
  • Mesmo nome da classe e sem tipo de retorno (nem void).
  • Parâmetros diferentes = sobrecarga (variações do mesmo construtor).
  • Sem construtor declarado, Java cria o default sem parâmetros.

Como reconhecer na prova

  • Método com nome igual ao da classe e sem retorno → construtor.
  • Vários construtores com listas de parâmetros diferentes → sobrecarga.
  • new aloca, o construtor inicializa.

Pegadinha

Se você declara qualquer construtor, o default sem parâmetros deixa de existir. Então new Televisor() passa a não compilar até você declarar esse construtor. E construtor não tem herança: ele não é herdado.

06 Pacotes e garbage collector AZUL

Pacote organiza classes. O GC apaga o que ficou sem referência.

Quando o objeto morre

sem referência → GC
referência tv1 null
Televisor não existe
referência tv2 null
—

Objeto sem referência vira lixo.

Código: pacote, import e null

package br.com.escola.modelo;

import java.util.ArrayList;
import java.util.List;
// import java.util.*;  não pega subpacotes

public class Aluno {
  // ...
}

Televisor tv = new Televisor();
tv = null;   // objeto sem referência
// o GC libera a memória sozinho
  • package na 1ª linha do arquivo.
  • import pacote.Classe; ou import pacote.*; — o * não inclui subpacotes.
  • GC limpa objetos inalcançáveis; não existe destrutor explícito.

Como reconhecer na prova

  • package no topo; import logo depois.
  • obj = null ou sair do escopo → candidato a coleta.
  • Pedir “quantos objetos ficam para o GC?” → conte as referências vivas.

Pegadinha

O GC não é destrutor: você não controla quando ele roda. E System.gc() é só uma sugestão. Objeto ainda referenciado por outra variável não é coletado.

07 Herança CIANO

A subclasse nasce com o que a superclasse tem e acrescenta o que é só dela.

Árvore da herança

toque em uma classe

Toque numa classe para ver o que ela herda.

super(...) sobe a cadeia

1ª linha do construtor
Funcionario(...)super(nome, cpf)
PessoaFisica(...)super(nome)
Pessoa(...)this.nome = nome
—

Quem inicializa primeiro é a superclasse.

Código: extends e super

public class Pessoa {
  String nome;

  Pessoa(String nome) {
    this.nome = nome;
  }

  void mostra() {
    System.out.println(nome);
  }
}

class PessoaFisica extends Pessoa {
  String cpf;

  PessoaFisica(String nome, String cpf) {
    super(nome);       // 1ª linha
    this.cpf = cpf;
  }

  @Override
  void mostra() {
    super.mostra();    // método da super
    System.out.println(cpf);
  }
}
  • extends = herança (só uma superclasse em Java).
  • super(args) chama o construtor da superclasse, na 1ª linha.
  • super.metodo() chama a versão da superclasse.
  • Toda classe herda de Object: getClass, hashCode, equals, toString.

Como reconhecer na prova

  • extends + super → herança.
  • Método @Override na subclasse → especialização.
  • Classe filha herda atributos e métodos (respeitando o modificador de acesso).

Pegadinha

Construtor não é herdado. Se a superclasse não tem construtor sem parâmetros, a subclasse é obrigada a chamar super(...) com os argumentos certos. E Java não tem herança múltipla de classes.

08 final LARANJA

Três usos, três bloqueios: classe não herda, método não sobrescreve, variável não muda.

Teste cada bloqueio

erro de compilação
final class Conta tentar extends

ERRO: cannot inherit from final Conta

final void calc() tentar sobrescrever

ERRO: calc() in Filha cannot override

final int LIMITE = 10; tentar reatribuir

ERRO: cannot assign a value to final variable

Nada disso compila.

Código: os três usos

final class Conta { }        // não herda

class Base {
  final void calc() { }
}

class Filha extends Base {
  void calc() { }            // ERRO
}

final int LIMITE = 10;
LIMITE = 20;                 // ERRO
  • final class → ninguém faz extends (ex.: String).
  • final método → ninguém faz @Override.
  • final variável → recebe valor uma vez (constante: static final).

Como reconhecer na prova

  • final em classe/método → herança/sobrescrita proibidas.
  • static final → constante de classe (convenção: MAIÚSCULAS).
  • Atributo final pode ser inicializado no construtor (uma única vez).

Pegadinha

final em uma referência não congela o objeto: final List l impede l = outra, mas ainda permite l.add(...). E atributo final sem valor não compila (salvo se inicializado no construtor).

09 Polimorfismo MAGENTA

A referência é da superclasse; o método que roda é o da classe real do objeto.

Despacho para a classe real

Pessoa p = new ...
Pessoa p
PessoaFisica nome Ana · cpf 123
p.mostraClasse(); → ?

Troque o objeto e rode de novo.

Overriding x overloading

assinatura
OVERRIDING · herança mesma assinatura 
class Animal {
  void som() { }
}
class Cachorro extends Animal {
  @Override
  void som() { }   // igual
}
OVERLOADING · mesma classe parâmetros diferentes 
class Calc {
  int soma(int a, int b) {
    return a + b;
  }
  int soma(int a, int b, int c) {
    return a + b + c;
  }
}

As duas têm o mesmo nome; o resto muda.

instanceof e casting

ClassCastException
Pessoa p PessoaJuridica
PessoaFisica pf ?
—

Teste o cast com o tipo real incompatível.

Código: as três ideias juntas

Pessoa p = new PessoaFisica();
p.mostraClasse();   // PessoaFisica

// referência da superclasse
// só acessa o que Pessoa declara

if (p instanceof PessoaFisica) {
  PessoaFisica pf = (PessoaFisica) p;
  pf.mostraCpf();
}

Pessoa q = new PessoaJuridica();
PessoaFisica x = (PessoaFisica) q;
// ClassCastException em tempo de execução
  • Polimorfismo = herança + @Override + referência da superclasse.
  • Upcasting (sub → super) é automático.
  • Downcasting (super → sub) exige cast e instanceof para evitar erro.

Como reconhecer na prova

  • Super s = new Sub(); → polimorfismo (upcasting).
  • Mesma assinatura + @Override → overriding.
  • Mesmo nome + parâmetros diferentes + mesma classe → overloading.
  • (Sub) s + instanceof → downcasting/teste de tipo.

Pegadinha

Só métodos sobrescritos são polimórficos. Atributos e métodos static usam o tipo da referência. Também não dá para acessar métodos exclusivos da subclasse por uma referência da superclasse sem cast.

10 Classe abstrata AMARELO

É base incompleta: não nasce sozinha e obriga as filhas a completarem o contrato.

Não dá new; dá herança

abstract
—
abstractacelerar()
concretoligar() herdado

Tente criar a classe abstrata.

Código: base + filha concreta

abstract class Veiculo {
  abstract void acelerar();  // sem corpo

  void ligar() {             // concreto
    System.out.println("Ligado");
  }
}

class Automovel extends Veiculo {
  @Override
  void acelerar() {
    System.out.println("+1 km/h");
  }
}

class Aviao extends Veiculo {
  @Override
  void acelerar() {
    System.out.println("+10 km/h");
  }
}
  • abstract class não permite new.
  • Pode ter métodos concretos e abstratos.
  • A filha concreta implementa todos os abstratos com @Override.

Como reconhecer na prova

  • abstract na classe → não instancia.
  • abstract no método + ; → sem corpo, subclasse obrigada.
  • Pode ter construtor (chamado por super), atributos e métodos normais.

Pegadinha

Classe com um método abstrato precisa ser abstract. Se a filha não implementar todos, ela também vira abstrata. Método abstract não pode ser private, static nem final.

11 Interface AMARELO

É um contrato de assinaturas: quem assina implements precisa cumprir tudo.

O contrato DAO

implements
Escolha uma implementação.
obrigatóriosalvar()
defaultlog() herdado
staticversao()

Uma interface, várias classes.

Código: contrato + Java 8

interface DAO {
  void salvar();       // public abstract

  default void log() { // Java 8+
    System.out.println("salvou");
  }

  static int versao() {
    return 2;
  }
}

class AlunoDAO implements DAO {
  public void salvar() {  // obrigatório
    System.out.println("aluno");
  }
}

interface CRUD extends DAO, Estoque {
  // interface estende várias
}
  • Métodos são public abstract por padrão; atributos são public static final.
  • default tem corpo e é herdado; static pertence à interface.
  • implements aceita várias interfaces; extends entre interfaces também aceita várias.

Abstrata x interface

CLASSE ABSTRATA
  • extends (só uma)
  • métodos concretos + abstratos
  • atributos de instância
  • construtor existe
  • não permite new
INTERFACE
  • implements (várias)
  • só default/static têm corpo
  • só constantes
  • sem construtor
  • não permite new

Como reconhecer na prova

  • interface + métodos sem corpo + implements → contrato.
  • default em interface → método com corpo (Java 8+).
  • Várias interfaces em implements A, B → sem herança múltipla de classes.
  • Programar para a interface: DAO d = new AlunoDAO(); → polimorfismo.

Pegadinha

Ao implementar, o método precisa ser public (não pode reduzir o acesso). Interface não tem atributo de instância: campo declarado ali é constante. E new DAO() nunca compila.

12 Relacionamentos VERDE-LIMÃO

“É um” é herança; “tem um” pode ser associação, agregação ou composição.

Destruir o todo

o que acontece com as partes?
todo Time
Escolha uma relação.

Agregação: a parte sobrevive. Composição: a parte morre.

Código: como aparece

class Professor {
  Aluno orientando;      // associação
}

class Time {
  List<Jogador> jogadores; // agregação
}

class Casa {
  private List<Comodo> comodos
      = new ArrayList<>(); // composição
}
  • Associação: “usa/conhece”; objetos vivem independentes.
  • Agregação: “tem um” fraco; a parte existe sem o todo (losango vazio).
  • Composição: “tem um” forte; a parte morre com o todo (losango cheio).

Como reconhecer na prova

  • Atributo que é objeto de outra classe → relacionamento.
  • Lista criada dentro do todo e sem uso externo → composição.
  • Lista recebida no construtor e compartilhada → agregação.
  • extends → “é um”; nunca use herança só para reaproveitar código.

Pegadinha

UML: losango vazio = agregação; losango preenchido = composição. Prefira composição a herança quando a relação não for realmente “é um”.

13 Exceções LARANJA

O erro sai do ponto problemático e sobe até um catch compatível; o finally sempre roda.

Fluxo try → catch → finally

linha por linha
try {
  int x = 10 / 0;
} catch (ArithmeticException e) {
  System.out.println("catch");
} finally {
  System.out.println("finally");
}
System.out.println("fim");
saída: —
exceção: nenhuma ainda

Veja a exceção subir.

Hierarquia: checked x unchecked

Throwable
Throwableraiz
Toque em um nó.

Checked o compilador cobra; unchecked não.

Código: tratar, declarar, criar

try {
  int x = 10 / 0;
} catch (ArithmeticException e) {
  System.out.println("erro");
} finally {
  System.out.println("fim");
}

void ler() throws IOException {
  // checked: trata ou declara
}

class MinhaExcecao extends Exception {
  MinhaExcecao(String msg) {
    super(msg);
  }
}

try (FileReader f =
       new FileReader("a.txt")) {
  f.read();
} catch (IOException e) { }
  • try/catch/finally: finally sempre executa (fechar recursos).
  • Throwable → Error / Exception; RuntimeException = unchecked.
  • throw lança; throws na assinatura declara.
  • try-with-resources fecha AutoCloseable sozinho (Java 7+).

Como reconhecer na prova

  • try/catch/throw/throws → tratamento de exceções.
  • IOException e Exception → checked (compilador obriga).
  • NullPointerException, ArithmeticException, ArrayIndexOutOfBoundsException → unchecked.
  • Catch do mais específico para o mais genérico.

Pegadinha

Trocar a ordem dos catches (genérico primeiro) não compila. finally executa até quando há return no try. E capturar Exception para tudo esconde o erro real.

14 equals, hashCode e toString AZUL

== compara endereços; equals compara conteúdo (quando sobrescrito).

Mesmo conteúdo, referências diferentes

dois objetos
Produto a nome "Caneta" preço 2.0
Produto b nome "Caneta" preço 2.0
—

Rode e compare.

Código: os três sobrescritos

public class Produto {
  private String nome;
  private double preco;

  @Override
  public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Produto)) {
      return false;
    }
    Produto p = (Produto) o;
    return nome.equals(p.nome)
        && Double.compare(preco, p.preco) == 0;
  }

  @Override
  public int hashCode() {
    return Objects.hash(nome, preco);
  }

  @Override
  public String toString() {
    return nome + " R$ " + preco;
  }
}
  • == compara referências; equals compara conteúdo.
  • hashCode coerente: iguais → mesmo hash.
  • toString dá a representação em texto.

Como reconhecer na prova

  • @Override equals/hashCode/toString → vindos de Object.
  • == com objetos → compara referência.
  • Set/Map usando objetos próprios → precisa de equals + hashCode.

Pegadinha

Sobrescrever equals sem hashCode quebra HashSet/HashMap: dois objetos “iguais” caem em baldes diferentes. E equals(Produto p) não sobrescreve equals(Object) — use @Override para o compilador avisar.

15 Classes internas e enum ROSA

Classe dentro de classe precisa da externa; enum é uma lista fixa de constantes.

Interna, anônima e enum

new externa.new interna
—
enum Dia { SEG, SAB, DOM }

A interna não vive sem a externa.

Código: os três formatos

public class Escola {
  private String nome = "Alfa";

  class Turma {              // interna
    void mostrar() {
      System.out.println(nome);
    }
  }
}

Escola e = new Escola();
Escola.Turma t = e.new Turma();
t.mostrar();

Runnable r = new Runnable() { // anônima
  public void run() {
    System.out.println("oi");
  }
};

enum Dia {
  SEG(false), SAB(true), DOM(true);

  private final boolean folga;

  Dia(boolean folga) {
    this.folga = folga;
  }

  boolean isFolga() { return folga; }
}
  • Interna não-static: e.new Turma(); acessa membros da externa.
  • Classe anônima: implementa na hora, sem nome.
  • enum: constantes fixas, com atributos, construtor e métodos.

Como reconhecer na prova

  • Classe declarada dentro de outra → aninhada/interna.
  • new Interface() { ... } → classe anônima.
  • enum com lista de constantes → tipo enumerado.
  • Tipo.valueOf("X") e values() vêm do enum.

Pegadinha

Classe anônima só acessa variáveis locais efetivamente final. E enum não permite new de fora: as constantes já são as instâncias.

16 Coleções e generics AZUL

List guarda repetidos e ordem; Set recusa repetidos; Map liga chave a valor.

O mesmo dado nas três

List · Set · Map
List<String>
vazia
Set<String>
vazio
Map<String,Integer>
vazio
—

Adicione “Ana” duas vezes e observe o Set.

Código: programar para a interface

List<String> lista =
    new ArrayList<>();
Set<String> set =
    new HashSet<>();
Map<String, Integer> mapa =
    new HashMap<>();

lista.add("Ana");  // aceita repetir
set.add("Ana");    // ignora repetido
mapa.put("Ana", 10); // chave → valor

// List: ordem + repetidos
// Set: sem repetidos
// Map: chave única
  • Generics <String>: erro de tipo em compilação, sem cast.
  • List (ArrayList/LinkedList), Set (HashSet/TreeSet), Map (HashMap/TreeMap).
  • List l = new ArrayList<>() → programar para a interface = polimorfismo.

Como reconhecer na prova

  • List<T>, Set<T>, Map<K,V> → coleções + generics.
  • TreeSet/TreeMap → ordenados; HashSet/HashMap → por hash.
  • Set e chaves de Map dependem de equals/hashCode.

Pegadinha

List aceita repetidos — quem “elimina duplicados” é o Set. Em Map.put, a mesma chave substitui o valor. E não existe List<int>: use Integer.

17 Lambdas MAGENTA

Lambda é a forma curta de implementar uma interface com um único método.

Da classe anônima à lambda

passo a passo
1 · classe anônima 
Soma s = new Soma() {
  public int calc(int a, int b) {
    return a + b;
  }
};
2 · só a assinatura 
Soma s = (int a, int b) -> {
  return a + b;
};
3 · lambda final

Três formas de dizer a mesma coisa.

Código: interface funcional

@FunctionalInterface
interface Soma {
  int calcular(int a, int b);
}

Soma s = (a, b) -> a + b;
int r = s.calcular(2, 3);   // 5

List<String> nomes = List.of("Ana", "Bia");
nomes.forEach(x -> System.out.println(x));

Comparator<String> c =
    (a, b) -> a.compareTo(b);
// Runnable, Comparator: 1 método
  • Interface funcional: um único método abstrato (Runnable, Comparator).
  • (a, b) -> a + b = implementação curta.
  • @FunctionalInterface só documenta/valida essa regra.

Como reconhecer na prova

  • -> → lambda.
  • @FunctionalInterface ou interface com 1 método abstrato → alvo de lambda.
  • forEach(x -> ...) → percorrendo coleção.

Pegadinha

Lambda não substitui classe com vários métodos. Quando o corpo tem uma linha, return e chaves são opcionais; com várias linhas, precisa de { } e return.

18 Serialização AZUL

O objeto vira bytes, vai para o arquivo e depois volta a ser objeto.

Objeto → bytes → arquivo → objeto

transient fica fora
Produto nome: Caneta preco: 2.0 senha: 123
produto.ser 0 bytes

Grave e leia de volta.

Código: gravar e ler

public class Produto
    implements Serializable {
  private static final long serialVersionUID = 1L;
  private String nome;
  private transient String senha; // fora
}

class ProdutoPersiste {
  void gravar(Produto p) throws IOException {
    try (ObjectOutputStream out =
         new ObjectOutputStream(
           new FileOutputStream("p.ser"))) {
      out.writeObject(p);
    }
  }

  Produto ler() throws IOException,
      ClassNotFoundException {
    try (ObjectInputStream in =
         new ObjectInputStream(
           new FileInputStream("p.ser"))) {
      return (Produto) in.readObject();
    }
  }
}
  • implements Serializable é o requisito (interface marcadora).
  • ObjectOutputStream grava; ObjectInputStream lê.
  • transient não é serializado (volta null/0).

Como reconhecer na prova

  • implements Serializable → objeto pode ser gravado.
  • writeObject / readObject → gravação e leitura.
  • transient → atributo fora da serialização.
  • serialVersionUID → controle de versão da classe.

Pegadinha

static também não é serializado (pertence à classe, não ao objeto). Se a classe não implementa Serializable, writeObject lança NotSerializableException.

19 Princípios de projeto AMARELO

Alta coesão e baixo acoplamento; SOLID para mudar sem quebrar.

Compare os dois extremos.

SOLID em 5 toques

toque na letra
S · uma responsabilidade por classe

S, O, L, I, D.

Código: depender da abstração

interface Pagamento {
  void pagar(double valor);
}

class Pix implements Pagamento {
  public void pagar(double v) { }
}

class Pedido {
  private Pagamento pagamento; // DIP

  Pedido(Pagamento p) {
    this.pagamento = p;
  }
}
  • S uma responsabilidade; O aberto para extensão, fechado para mudança.
  • L a subclasse substitui a superclasse sem quebrar.
  • I interfaces pequenas; D depender de abstrações.

Como reconhecer na prova

  • Classe que faz tudo → baixa coesão; muitas dependências fixas → alto acoplamento.
  • Pedido recebendo Pagamento (interface) → inversão de dependência.
  • Novo tipo sem alterar o código existente → aberto/fechado.
  • Preferir composição a herança quando não for “é um”.

Pegadinha

SOLID não é lei: aplicar sem necessidade gera classes demais. E baixo acoplamento não é zero acoplamento — algum é inevitável.
